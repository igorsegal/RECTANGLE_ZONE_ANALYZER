# CANONICAL Block 04 — Development Statistics

Block 04 не перечитывает рыночную базу и не повторяет поиск formation-событий.

Единственный вход:

```text
CANONICAL/03out/03_REACTION_SCREEN.csv
```

## Единый поток событий

С этого блока `ENGULF_2` и `ENGULF_3` **не являются отдельными исследовательскими ветками**.

После подтверждения формирования все события считаются одним типом объекта:

```text
CONFIRMED_ENGULF_RECTANGLE
```

И идут одним непрерывным потоком:

```text
formation -> rectangle -> return/touch -> reaction or breakout
```

Техническое поле `FormationType` может оставаться в исходном Block03-файле только для аудита происхождения события, но Block04 и последующие блоки не используют его для разделения выборки.

## Progress

Progress остаётся только необязательным признаком там, где он физически определён.

Он не создаёт отдельную ветку `ENGULF_3`; это просто дополнительное свойство части событий общего потока.

## Основной показатель

```text
ReactionPct =
REACTION_FIRST /
(REACTION_FIRST + BREAKOUT_FIRST)
```

Остальные lifecycle-исходы отдельно учитываются в `Other`, но не входят в знаменатель этой доли.

Дополнительно считаются направления, таймфреймы и progress-группы там, где progress существует.

## Чего Block 04 не делает

- не открывает BIN-файлы;
- не пересчитывает formation;
- не разделяет поток на ENGULF_2 / ENGULF_3;
- не меняет определения touch/reaction/breakout;
- не подбирает thresholds;
- не оптимизирует параметры;
- не считает TP/SL/PF;
- не использует 2024+ для принятия development-решений.

После этого остаётся одна независимая OOS-проверка на 2024+ для единого потока.
